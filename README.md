# 贴吧网页端助手（新版 UI 增强）

一个针对百度贴吧**新版网页端**的油猴脚本（当前版本 v0.7.3）：

| 问题 | 脚本里的做法 | 状态 |
| --- | --- | --- |
| 1. 新版没有旧版那种「分标签页」 | 顶部注入一条页面标签栏，把 看贴/图片/吧主推荐/视频/首页 等入口集中成可点击的标签 | 通用实现，已在模拟页验证 |
| 2. 进吧默认「热门」排序 | 自动找到排序栏里的「最新」并点击；只点一次，不反复触发；可整体关闭 | 通用实现，已在模拟页验证 |
| 3. 帖子页也默认「热门」排序 | 自动点帖子页排序栏（热门/正序/倒序）里的「正序」；**你手动改过排序后就不再插手** | 已按实测 DOM 实现 |
| 4. 楼中楼头像和主楼一样大、无限展开 | **只压缩楼中楼**（`.lzl-wrapper` 内）：头像 40px → 16px、行高 26→17px、日期行 16px、左侧竖线 + 淡底；主楼、楼层回复、回复框头像一律不动 | 已按实测 DOM 精修，有回归测试守着 |
| 5. 楼中楼太多会把楼层撑得很长 | **楼中楼分页**：像旧版贴吧那样按页翻，每页默认 10 条，单页文字超过 1200 字也会提前翻页；底部分页条 `‹ 上一页 1 2 3 下一页 › 共 N 条`，点页码直接跳 | 已实现，含页码状态保持 |

## 安装

**一键安装（推荐）**：装好 [Tampermonkey](https://www.tampermonkey.net/)（Edge / Chrome 都可）后，直接打开：

```
https://raw.githubusercontent.com/Stontar/tieba-helper/main/tieba-helper.user.js
```

Tampermonkey 会自动弹出安装界面，点「安装」即可。之后脚本带 `@updateURL`，新版本会自动更新。

手动安装（备用）：

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 打开 Tampermonkey 管理面板 → 「添加新脚本」，把 `tieba-helper.user.js` 全文粘贴进去保存。
3. 打开贴吧页面即可生效。右下角 ⚙ 可逐项开关。

> 脚本以 `@run-at document-start` 加载，因此首次打开贴吧时样式和网络钩子会尽早就位。

## 使用

- **排序**：吧页自动切到「最新」；帖子页自动切到「正序」（不再是热门）。默认只切一次；如果你自己点了排序标签，脚本就不会再抢回来。
- **标签栏**：页面顶部一条「页面 [看贴] [图片] [吧主推荐] [视频]」，点击在新标签页打开；右侧 × 可隐藏。
- **楼中楼压缩 + 分页**：默认开启。每块楼中楼按页显示，默认 **10 条/页**，一页文字超过 1200 字也会提前翻页；底部是 `‹ 上一页 1 2 3 … 下一页 › 共 N 条`，点页码直接跳转。
  - 贴吧自带的「展开更多回复」交给页码条接管：翻到最后一页还点「下一页」时，脚本会自动去点它加载下一批。
  - **不会跳过内容**：如果当前这页还没装满（比如只加载了 3 条），点「下一页」会先把后面的加载出来、**留在本页把这 10 条填满**，等你再点一次才翻页。
  - 翻到第几页会记住：滚屏、站点重渲染（虚拟列表重建 DOM）后仍然停在同一页。
  - **翻页时视角会跟过去**：点页码/下一页后，视口会自动对到新一页的第一条回复；如果下一页比较短，也不会让你看到楼下、误以为是这一页的内容。
- **每页几条**：⚙ → 「每页楼中楼条数」，可选 5 / 10 / 15 / 20 / 不分页。
- **设置**：点右下角 ⚙，按项显示「开/关」，点击即切换并记住。

## 诊断模式（重要）

因为新版贴吧是灰度发布，且页面的 class 名是前端框架生成的，**楼中楼那两项（压缩 + 分页）需要拿到你实际页面的结构才能真正精准**。

用法（v0.2 起一键完成）：

1. 打开新版贴吧的「帖子页面」，先手动展开几个楼中楼。
2. 点右下角 ⚙ → 「诊断捕获」。
3. 模式保持「精简（推荐）」，点「捕获本页」。
4. **捕获完成会自动复制到剪贴板**，直接粘贴给我即可；如果没复制成功，点「复制」或「下载」。

「精简」模式输出的是帖子主体 + **每个元素的行内计算样式**（display / 字号 / 行高 / padding / 尺寸），体积通常 10–100 KB，刚好能看清楼中楼为什么占空间；「完整」模式额外输出整页结构树和 class 清单，体积更大。

捕获内容**不含登录 Cookie**；但会带页面上的公开文本（用户名、帖子标题、回复内容），介意的话可以先扫一眼再发。

## 已知限制

- 第 1、2 项按「文案 + 可见性 + 真实点击」实现，对新版贴吧的类名变化不敏感；但如果新版把「最新/热门/正序」改成纯图标或英文，需要另加文案映射。
- 帖子页「正序」是按文案匹配 `.sub-tab-container > .sub-tab-item` 里文字为「正序」的那一项；你手动点过排序之后，脚本就不会再抢。
- 第 4 项已按实测 DOM 精确锁定到新版贴吧的 `.lzl-wrapper / .pb-lzl-item`：**只有楼中楼会被压缩**，主楼 `.image-text`、楼层 `.pb-comment-item`、回复框 `.avatar-box` 的头像保持 40px 原样。如果哪天贴吧把 `.lzl-wrapper` 改名，楼中楼样式会静默失效（不会误伤主楼），届时用诊断捕获重新拿一次结构即可。
- 楼中楼分页依赖 `.lzl-wrapper` 的**直接子元素** `.pb-lzl-item`：贴吧如果改成别的嵌套层级，分页会自动不生效（只是不翻页，不会出错）。
- 分页只对**已经加载到页面上的**楼中楼生效；贴吧本身是懒加载的，要先把回复加载出来，页码才会变多。
- 楼中楼那一块是虚拟列表渲染的，滚动时会被销毁重建。脚本按回复的 `data-id` 记住你在第几页，并且**只在状态真的变了才改 DOM**（否则每轮都会触发回流，页面会上下抖动）。
- 未处理：楼层跳转（新版没有楼层号、注释与广告行又会让序号漂移，精度无法保证，已按你的要求移除）、广告、暗色模式细节、图片查看器等其它体验问题。

## 发布与分发

三种常见路线：

| 路线 | 优点 | 代价 |
| --- | --- | --- |
| **Greasy Fork** | 油猴脚本的标准仓库，能被搜到、一键安装，平台自动处理自动更新 | 站点在境外，国内访问偶尔慢 |
| **GitHub / Gitee + raw** | 国内可用（Gitee 更快）、完全自己掌控 | 用户点链接手动装；自动更新要自己写 `@updateURL` / `@downloadURL` |
| **Cloudflare Pages / Vercel 等静态托管** | 可以做个漂亮的安装页，用自己的域名 | 多一步部署 |

### 路线 A：Greasy Fork（建议先发这里）

1. 打开 <https://greasyfork.org> 注册或登录（支持 GitHub 账号）。
2. 右上角头像 →「发表脚本」（Create script）。
3. 把 `tieba-helper.user.js` 全文粘进代码框；语言选「中文(简体)」。
4. 简介可以取 README 开头那几行；标签建议填：`贴吧`、`百度贴吧`、`tieba`、`油猴`。
5. 发布后会得到一个安装地址，形如
   `https://greasyfork.org/scripts/xxxxx/code/tieba-helper.user.js`
   —— 把它发给吧友就行，Tampermonkey 会自动弹安装框。
6. **更新**：改代码、把 `@version` 加一，回到该脚本页面点「更新脚本」，平台会推送更新，用户端自动提示升级。

> Greasy Fork 会给脚本自动补 `@updateURL` / `@downloadURL` 并指向自己，所以走这条路**不用**手写这两个字段。

### 路线 B：GitHub / Gitee

1. 建一个仓库，比如 `tieba-helper`，把 `tieba-helper.user.js`、`README.md`、`LICENSE` 推上去。
2. 拿到 raw 地址：
   - GitHub：`https://raw.githubusercontent.com/<账号>/tieba-helper/main/tieba-helper.user.js`
   - Gitee：`https://gitee.com/<账号>/tieba-helper/raw/main/tieba-helper.user.js`
3. 在脚本头部 `==UserScript==` 块里补两行（文件里已有「发布提示」注释示范）：
   ```
   // @updateURL    <上面的 raw 地址>
   // @downloadURL  <上面的 raw 地址>
   ```
4. 安装链接直接用 raw 地址（必须是能直接返回 `.user.js` 文本的地址，不要用 GitHub 的网页预览页）。
5. **更新**：push 新代码 + 提高 `@version`；Tampermonkey 默认每天检查一次更新，用户无需重装。

### 发布前检查清单

- [ ] `@version` 已递增（这是触发自动更新的唯一依据）
- [ ] `@namespace` / `@author` / `@homepageURL` / `@supportURL` 换成了自己的
- [ ] 走 GitHub/Gitee 的话，`@updateURL` / `@downloadURL` 是能直接访问的 raw 地址
- [ ] 用**干净的浏览器**（没装其它贴吧脚本）实测：安装 → 打开帖子页 → 排序自动切正序 → 标签栏 → 楼中楼压缩 → 楼中楼翻页
- [ ] 说明里写清「不上传任何数据」；诊断捕获只在**用户手动点击**时把结构打包到剪贴板/本地下载
- [ ] 公开仓库前确认 `refs/` 里的截图、诊断样本不含别人的用户名等信息（或干脆不提交 `refs/`）

### 隐私与合规说明（建议写进脚本简介）

- 脚本不向任何自建服务器发请求，也不做统计埋点；开关状态用 `GM_setValue` 存在本地。
- 诊断捕获产物只写入剪贴板和本地下载，不会上传。
- 脚本只是模拟点击排序、加载、翻页等 UI 操作，属于客户端增强；被风控的概率很低但不为零，建议在简介里提示用户自行判断。

测试点为：吧页排序切「最新」、帖子页排序切「正序」、标签栏注入、设置浮标、楼层跳转框已移除、楼中楼分页（默认 10 条/页、页码跳转、上一页/下一页边界、末页点下一页自动加载下一批且不跳过内容、下拉改条数/不分页）、滚动稳定性（稳定后不再改写 DOM）、虚拟列表重建 wrapper 后仍停在第 N 页、翻到更短的一页后视角跟到新一页第一条、诊断捕获、无运行时异常，以及楼中楼头像 16px、正文行高 17px、单条 ≤60px，而主楼与楼层头像仍为 40px 的回归检查。
